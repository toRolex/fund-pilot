# PRD-001: 本地量化信号工作台 — 最小端到端路径

## Problem Statement

作为个人基金投资者，我需要在一个本地优先的工作台中管理自定义基金列表、拉取历史净值与实时数据、运行多策略信号回测、并在浏览器中查看结果。现有工具（xalpha、akquant）各自独立工作，缺少一个将它们粘合在一起的本地应用：没有统一的基金列表管理，没有持久化的信号存储，没有可视化的前端界面，也没有定时调度的自动化能力。每次使用都需要手动跑脚本、记结果，无法长期跟踪信号变化。

## Solution

构建一个 Monorepo 结构的本地量化信号工作台，以 `xalpha` 作为场外基金数据源，以 `akquant` 作为回测引擎，通过 `FastAPI` 后端提供 REST 接口，`React + TypeScript + Vite` 前端（`Recharts` 图表 + `TanStack Query` 数据管理）提供可视化界面，`SQLite` 做本地持久化，`crontab` 做定时调度。全链路运行在本地 Mac 上，不做推送、不做自动交易。xalpha 提供净值、估值百分位、QDII 预测等数据；akquant 负责均线、网格、动量轮动等策略回测。

## User Stories

1. 作为一个本地用户，我想要维护一个自定义基金列表（添加/删除/查看）， so that 我只关注自己关心的基金品种
2. 作为一个用户，我想要查看每只基金的基本信息（名称、类型、最新净值、估值），so that 我可以快速了解基金当前状态
3. 作为一个用户，我想要查看基金 5 年以上的历史净值曲线，so that 我可以分析长期走势
4. 作为一个用户，我想要运行均线策略回测并查看买卖信号，so that 我可以判断趋势跟踪的有效性
5. 作为一个用户，我想要运行估值百分位策略并查看当前百分位，so that 我可以判断基金是否处于低估/高估区间
6. 作为一个用户，我想要运行网格策略并查看网格区间与触发价，so that 我可以执行网格交易
7. 作为一个用户，我想要运行动量轮动策略并查看轮动排序，so that 我可以选择动量最强的品种
8. 作为一个用户，我想要在网页上以表格形式查看所有信号结果，so that 我可以一目了然地看到当前信号状态
9. 作为一个用户，我想要在网页上以 Recharts 图表查看净值曲线与信号叠加图，so that 我可以直观理解信号触发时机
10. 作为一个用户，我想要通过 crontab 定时更新数据，so that 我不需要手动触发数据拉取
11. 作为一个用户，我想要查看所有历史信号运行记录，so that 我可以对比不同时间点的信号差异
12. 作为一个用户，我想要查看 QDII 基金的净值预测，so that 我可以提前了解 T-1/T-0 估值
13. 作为一个用户，我想要多策略并行运行并对比结果，so that 我可以选择最适合当前市场的策略
14. 作为一个用户，我想要工作台在本地 Mac 上完全离线运行（除数据拉取外），so that 我的投资数据不会泄露到第三方
15. 作为一个用户，我想要 SQLite 数据库保存所有 price_snapshot 数据，so that 我不需要每次都重新拉取历史数据

## Implementation Decisions

### Monorepo 结构

```
fund-signal-workbench/
├── backend/          # FastAPI + xalpha + akquant
├── frontend/         # React + TypeScript
├── data/             # SQLite DB + 缓存文件
├── scripts/          # crontab 调度脚本
└── docs/             # PRD / ADR / 文档
```

### 后端模块设计

| 模块 | 职责 | 核心依赖 |
|------|------|----------|
| `data_layer` | watchlist CRUD、price_snapshot 缓存读写、xalpha 数据拉取 | xalpha, SQLite |
| `signal_engine` | 调用 akquant 运行策略回测，将结果写入 signal_run + signal_item | akquant |
| `api` | FastAPI 路由层，暴露 `/api/watchlist`、`/api/signals`、`/api/prices` | FastAPI |
| `scheduler` | crontab 入口，定时触发数据更新与信号重算 | crontab |

### SQLite 最小表结构

```sql
-- 关注列表：合并 fund 基本信息与 watchlist（单表，软删除）
CREATE TABLE watchlist (
    code        TEXT PRIMARY KEY,    -- 基金代码，如 "501018"
    name        TEXT NOT NULL,       -- 基金名称（xalpha 填充，原始分类名）
    type        TEXT NOT NULL,       -- xalpha 返回的基金分类原文，如 "混合型-偏股"
    is_active   INTEGER DEFAULT 1,  -- 1=关注中, 0=已移除（软删除）
    added_at    TEXT NOT NULL,       -- ISO 8601
    updated_at  TEXT NOT NULL        -- 基本信息最后更新时间
);

-- 每次信号运行的元数据
CREATE TABLE signal_run (
    id          INTEGER PRIMARY KEY,
    strategy    TEXT NOT NULL,     -- "ma" | "pe_percentile" | "grid" | "momentum" | 未来扩展
    run_at      TEXT NOT NULL,     -- ISO 8601
    status      TEXT NOT NULL      -- "running" | "completed" | "failed"
);

-- 信号条目：每只基金在每次运行中的信号结果
CREATE TABLE signal_item (
    id          INTEGER PRIMARY KEY,
    run_id      INTEGER NOT NULL REFERENCES signal_run(id),
    fund_code   TEXT NOT NULL REFERENCES watchlist(code),
    signal      TEXT NOT NULL,     -- 策略自定义信号词，如 "buy"/"sell"/"hold"（均线）, "undervalued"/"overvalued"/"neutral"（估值）, "rank_N"（动量）
    value       REAL,              -- 策略数值（如百分位、动量得分）
    detail      TEXT               -- 策略自由 JSON，前端按 strategy 字段条件渲染
);

-- 净值快照：缓存历史日线数据
CREATE TABLE price_snapshot (
    id          INTEGER PRIMARY KEY,
    fund_code   TEXT NOT NULL REFERENCES watchlist(code),
    date        TEXT NOT NULL,     -- YYYY-MM-DD
    nav         REAL NOT NULL,     -- 单位净值
    acc_nav     REAL,              -- 累计净值
    updated_at  TEXT NOT NULL,
    UNIQUE(fund_code, date)
);
```

### API 契约

| 端点 | 方法 | 描述 |
|------|------|------|
| `/api/watchlist` | GET | 返回关注列表（`is_active=1`） |
| `/api/watchlist` | POST | 添加基金到关注列表（`{code: string}`），添加后立即拉取 xalpha 数据填充基本信息与净值 |
| `/api/watchlist/:code` | DELETE | 移除基金（软删除 `is_active=0`） |
| `/api/signals` | GET | 返回最新信号运行结果（支持 `?strategy=xxx` 过滤） |
| `/api/signals/run` | POST | 手动触发信号运行（`{strategy: string, fund_codes: string[]}`），前端并发调用多次实现多策略对比 |
| `/api/prices/:code` | GET | 返回某基金历史净值（`?start=YYYY-MM-DD&end=YYYY-MM-DD`） |
| `/api/qdii/:code` | GET | 返回 QDII 净值预测 |

### 数据流

```
crontab → scripts/fetch_daily.py → xalpha 拉取净值 → 写入 price_snapshot
crontab → scripts/run_signals.py → akquant 生成信号 → 写入 signal_run + signal_item
前端 → GET /api/signals → FastAPI 读 SQLite → 返回 JSON
前端 → GET /api/prices/:code → FastAPI 读 price_snapshot → 返回净值数组
```

### 技术选型

- Python >= 3.12，通过 `uv` 管理依赖与运行
- FastAPI + uvicorn 作为后端 HTTP 服务
- React + TypeScript + Vite 作为前端
- TanStack Query (React Query) 作为前端数据管理（缓存、loading/error 三态管理）
- Recharts 作为前端图表库（轻量，React 原生声明式 API）
- SQLite 通过 Python 标准库 `sqlite3` 访问，不使用 ORM
- crontab 定时任务直接调用 `python scripts/*.py`

### xalpha 集成方式（数据源）

- 沿 `xalpha.fundinfo` 获取基金基本信息与净值
- 沿 `xalpha.get_daily` 获取历史日线数据
- 沿 `xalpha.PEBHistory` 获取估值百分位
- 沿 `xalpha.QDIIPredict` 获取 QDII 净值预测
- 不复写、不重构 xalpha 内部逻辑，仅作为调用方
- xalpha 的缓存机制（CSV/SQL）与本地 price_snapshot 表互不干扰

### akquant 集成方式（回测引擎）

- 通过 akquant 策略框架运行均线、网格、动量轮动等策略回测
- 估值百分位数据由 xalpha 提供，akquant 负责均线/网格/动量策略计算
- 信号输出标准化为本工作台的 signal_item 格式

## Testing Decisions

### 测试原则

- 只测试外部行为（API 响应格式、数据库写入结果），不测试实现细节
- FastAPI 路由使用 `httpx.AsyncClient` + `TestClient` 做集成测试
- 数据层测试使用内存 SQLite，不留磁盘文件
- xalpha 网络调用通过 `pytest.importorskip` + mock 隔离，不依赖真实网络

### 测试覆盖模块

| 模块 | 测试类型 | 参考先例 |
|------|----------|----------|
| `data_layer` | 单元测试：fund CRUD / watchlist 操作 | xalpha `tests/test_info.py` 的 pytest 风格 |
| `signal_engine` | 单元测试：给定输入 DataFrame，验证信号输出格式 | xalpha `tests/test_universal.py` 的数据驱动风格 |
| `api` | 集成测试：`/api/funds`、`/api/signals` 的 200/400 响应 | FastAPI 官方 TestClient 模式 |
| `scripts/` | 端到端：脚本运行后验证 SQLite 中有数据 | 简单 subprocess 验证 |

## Out of Scope

- 自动交易执行：本工作台只生成信号，不下单
- 推送通知：不做邮件/微信/短信推送
- 用户认证：本地单用户使用，不需要登录注册
- 云端部署：明确本地 Mac 运行，不做 Docker / 云服务器部署
- 多账户管理：单 watchlist，不支持多用户多账户
- 实时行情推送：通过定时拉取更新，不做 WebSocket 实时推送
- 回测收益对比与组合模拟：首期只做信号生成，不做 mul/组合模拟
- 移动端适配：首期只做桌面端浏览器界面

## Further Notes

- xalpha 的缓存机制（CSV/SQL）应被尊重：本地 price_snapshot 表与 xalpha 内部缓存是两个层级，互不干扰
- Pandas/Numpy 兼容性需遵循 xalpha AGENTS.md 的约定：Pandas 1.x-3.x、Numpy 1.x-2.x
- 前端使用 Recharts 实现净值曲线与信号叠加图，轻量 React 原生渲染
- crontab 频率建议：每个交易日 15:30（收盘后）触发一次全量更新
- 未来可扩展：回测报告生成、基金组合模拟、信号邮件推送等，但均不在本期范围内
- Project Skills: `.claude/skills/akquant` 和 `.claude/skills/akshare` 提供开发时参考
